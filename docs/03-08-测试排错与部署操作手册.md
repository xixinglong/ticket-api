# 03-08-测试排错与部署操作手册

本节用于后续手动验收和新环境复现。下面命令是操作说明，2026-10-31 本轮没有执行 Maven 构建、测试、启动或打包，也没有改动真实数据库。先确保使用自己的练习库。

## 1. 三种测试分别回答什么

| 层次 | 项目中的例子 | 能证明 | 不能证明 |
| --- | --- | --- | --- |
| 单元测试 | TicketServiceTest、TicketPaginationUnitTests | 业务分支、参数计算、调用约定 | MySQL 真正提交或回滚 |
| MVC 测试 | ApiExceptionHandlerTests | JSON、状态码、错误脱敏 | 真实登录与数据库整体可用 |
| 集成测试 | TicketSecurityTests、Cancellation/Claim/Resolution/PaginationTests | 安全链、数据库状态、事务与竞争 | 别人的新机器已能成功部署 |

MockMvc 不是正在监听 8080 的真实 HTTP 服务。模拟 Service 可以隔离响应处理，但不能替代真实事务测试。PowerShell 脚本则请求已启动服务，它测试的是该进程加载的代码；修改源文件后没重启，仍可能测到旧实现。

## 2. 运行测试前检查

在 PowerShell A 按 [[03-03-MyBatis与环境配置]] 配置 DB_*。确认数据库是专用练习库且表结构正确。测试会插入、更新和清理自身数据，不应连接生产库；不要与手工业务写入同时进行。

后续明确允许测试时执行：

~~~powershell
Set-Location 'C:\xixl-study\java-labs\ticket-api'
.\mvnw.cmd test
~~~

预期最后 BUILD SUCCESS，所有报告失败和错误为 0。若失败，先看第一个测试失败或编译错误，而不是只复制最后一行 Help 1。

针对本次新增且不连接数据库的错误契约，也可以单独运行：

~~~powershell
.\mvnw.cmd '-Dtest=ApiExceptionHandlerTests' test
~~~

此命令仍会执行 Maven 编译阶段，不能当作绕过“未授权不构建”的办法。单独通过也不代表全套集成测试通过。

## 3. 怎么阅读报告

报告位于 target/surefire-reports。查看 tests、failures、errors、skipped，并记录报告修改时间与对应代码状态。只读汇总：

~~~powershell
Get-ChildItem .\target\surefire-reports\TEST-*.xml | ForEach-Object {
    $report = [xml](Get-Content -LiteralPath $_.FullName -Raw)
    [pscustomobject]@{
        Name = $report.testsuite.name
        Tests = $report.testsuite.tests
        Failures = $report.testsuite.failures
        Errors = $report.testsuite.errors
        Skipped = $report.testsuite.skipped
        Modified = $_.LastWriteTime
    }
}
~~~

现有旧报告共 63 项，失败、错误、跳过均为 0。它形成于新增分页、错误处理及本轮其他修改之前。不要在修改后仍引用它为“当前全部通过”，也不要把新加的测试数量自动加到通过数里。

## 4. 启动与手工接口验收

在 A 设置四个 LAB_* 登录密码后启动：

~~~powershell
.\mvnw.cmd spring-boot:run
~~~

看到 Tomcat started on port 8080 与 Started TicketApiApplication 后保持 A 打开。若端口占用，先找到原先运行本项目的窗口，按 Ctrl+C 停止，再启动；不要直接结束所有 java 进程。

必要时只读查端口占用：

~~~powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen |
    Select-Object LocalAddress, LocalPort, OwningProcess
~~~

在 B 顺序运行四个脚本：

~~~powershell
.\scripts\Test-TicketPermissions.ps1
.\scripts\Test-TicketClaim.ps1
.\scripts\Test-TicketResolve.ps1
.\scripts\Test-TicketPagination.ps1
~~~

每个脚本结束后先记录工单编号和结果。DBeaver 检查状态、处理人、事件数量和顺序。脚本最后的退出 204 属于会话清理，不代表工单又进行了一次业务动作。

## 5. 常见失败定位表

| 错误 | 处理方向 |
| --- | --- |
| nvoke-RestMethod 无法识别 | 少了 I，检查拼写 |
| org.junit.jupiter.api 不存在 | 检查测试是否放进 src/main/java，及 test 依赖 |
| 编译成功但启动失败 | 看后续异常；端口和配置问题发生在启动阶段 |
| 8080 已使用 | 旧实例仍在运行，确认后停止旧进程 |
| 预期 403 实际 204 | 检查负向请求是否仍带旧 CSRF header |
| 预期 204 实际 409 | 工单已被操作，重新查询状态；不要盲目重试 |
| 预期查到工单实际 404 | 检查当前身份、工单编号与可见性 |
| 500 INTERNAL_ERROR | 记下 requestId，查看 A 中对应服务端堆栈 |
| SQL 在 INDEX 附近 1064 | 检查完整语句选择、逗号与语句上下文 |

开发时记录“预期—实际—原因—修复—复查”，比保存一大段没有结论的日志更有用。不要把密码、Cookie 或 CSRF token 放进共享截图。

## 6. 新环境部署清单

以下是待执行流程，当前没有生成或验收新的 Jar。

1. 准备 Java 21 与 MySQL 8.4 系列，记录实际 java -version 和 SELECT VERSION()。pom.xml 声明 Spring Boot 4.1.2、MyBatis Starter 4.1.0；这是本项目版本，不是“网上最新版”。
2. 拷贝项目源码和 Maven Wrapper。Maven Wrapper 首次使用可能需要网络下载依赖。
3. 在新练习库依次执行 sql/01-schema.sql 两张表；旧库先核对结构，只执行缺失变更。应用账号应具备该练习库所需的 SELECT、INSERT、UPDATE、DELETE 权限，建库建表由管理账号完成。
4. 设置 DB_* 和四个 LAB_*，不修改源码写死密码。
5. 执行测试，保留新报告。确认通过后再执行打包。

~~~powershell
.\mvnw.cmd package
Get-ChildItem .\target\*.jar
~~~

package 会包含测试阶段；不要为追求成功跳过失败的测试。默认预期文件名是 ticket-api-0.0.1-SNAPSHOT.jar，但应以上一条列出的实际文件为准。

停止原 8080 服务后，在同一已配置环境的终端执行：

~~~powershell
java -jar .\target\ticket-api-0.0.1-SNAPSHOT.jar
~~~

日志默认打印到这个终端，没有假定已配置日志文件。需要保存时使用本机重定向或日志配置，并记录具体路径与保留方式。停止仍使用 Ctrl+C。

## 7. 部署验收不是“能启动”就结束

至少演示：登录、创建、查询、取消；另一组工单接单和完成；分页；停止并重启后重新登录查旧单。另在独立练习环境观察缺少配置、错误数据库地址的表现。数据库连接可能延迟到第一次访问时建立，所以 Started 不足以证明数据库可用，必须实际请求数据库接口。

不要停止共享数据库来做故障练习。可在独立终端使用错误地址并换到空闲端口，观察后退出，原终端配置不受影响。

当前服务仅监听 127.0.0.1。本课程尚未验收公网部署、HTTPS、用户注册、限流和生产审计，不要把本地练习项目直接当作生产交付。
