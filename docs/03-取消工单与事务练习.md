## 本次完成的功能

新增 POST /api/tickets/{id}/cancel。取消时先确认工单属于练习用户，再执行两条 SQL：

1. 将 tickets 中该工单的 OPEN 状态改为 CANCELLED。
2. 在 ticket_events 中新增一条 CANCEL 记录。

TicketService.cancel 上的 @Transactional 将两次写入放在同一个事务中。Controller 调用 Spring 管理的 Service 代理；若写记录抛出运行时异常，事务会撤销状态更新。

TicketMapper.xml 的 UPDATE 同时检查 id、creator_id 和 OPEN 状态。Service 检查更新行数；即使前面查询到了工单，最终没有更新成功也不能插入成功记录。

本阶段使用服务端固定练习用户 1001，不从请求中接受操作者编号。这只是事务学习阶段，尚未实现登录或完整的接口权限控制。原来的 GET 查询也尚未按登录身份过滤。

## 在 PowerShell 操作

如果旧服务仍在运行，先在它的窗口按 Ctrl+C。回到已设置 DB_URL、DB_USER、DB_PASSWORD 的项目根目录终端，运行：

~~~powershell
.\mvnw.cmd spring-boot:run
~~~

等待启动成功后，在第二个 PowerShell 窗口创建一张专门用于取消练习的工单：

~~~powershell
$base = 'http://127.0.0.1:8080'
$json = @{ title = 'Cancellation practice'; description = 'Verify state and event together' } | ConvertTo-Json
$ticket = Invoke-RestMethod -Method Post -Uri "$base/api/tickets" -ContentType 'application/json' -Body $json
$ticket
$response = Invoke-WebRequest -UseBasicParsing -Method Post -Uri "$base/api/tickets/$($ticket.id)/cancel"
$response.StatusCode
Invoke-RestMethod -Method Get -Uri "$base/api/tickets/$($ticket.id)"
~~~

预期取消响应为 204，查询结果的 status 为 CANCELLED。204 没有响应体。

## 在 DBeaver 核对

使用本机 ticket_lab 连接，将两处 123 替换为刚才的实际工单编号，分别执行完整语句：

~~~sql
SELECT id, title, creator_id, status FROM ticket_lab.tickets WHERE id = 123;
SELECT id, ticket_id, actor_id, action, created_at FROM ticket_lab.ticket_events WHERE ticket_id = 123 ORDER BY id;
~~~

应看到 CANCELLED 状态和一条 actor_id 为 1001、action 为 CANCEL 的记录。

再次发送取消请求会返回 409，PowerShell 会显示 HTTP 错误，数据库中不应增加第二条取消记录。不存在、格式非法或不属于练习用户的工单返回 404。

## 如何证明回滚

不要只看方法抛出了异常。TicketCancellationTests.eventFailureRollsBackState 使用真实 MySQL：

1. 创建并提交一张测试工单。
2. 通过 Spring 事务代理调用 cancel。
3. 在事件 Mapper 上注入测试异常；抛出异常前先查询，断言事务内部状态已经变为 CANCELLED。
4. 业务方法异常退出后，再次查询数据库，断言状态恢复为 OPEN、操作记录数量为 0。

测试类没有 @Transactional，因此这里的恢复必须由业务方法的事务完成，不会被测试框架的自动回滚掩盖。故障只在测试中注入，生产接口没有故障开关。
