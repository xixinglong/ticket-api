# 03-09-授课提纲与课后练习

这份提纲用于教第一次接触 Java 后端的同学。先让学生看见问题，再定位代码和验证结果。不要一开始讲完全部框架原理，也不要只让学生跟着复制。

## 一、推荐分成六次课

每次课约 60–90 分钟，时间只是教学安排建议，不是学习完成保证。课堂采用“解释 15 分钟 → 跟做 25 分钟 → 独立练习 20 分钟 → 复盘”节奏，可根据基础调整。

| 课次 | 核心问题 | 阅读材料 | 课堂演示 | 学生交付 |
| --- | --- | --- | --- | --- |
| 1 | HTTP 请求怎么走进 Java | 模块 01 | 在 IDE 跟踪创建调用链 | 标出 Controller、Service、Mapper |
| 2 | 重启后为什么数据还在 | 模块 02、03 | 建表检查、主键回填、重启查询 | SQL 与 HTTP 对照记录 |
| 3 | 为什么不能改别人的工单 | 模块 04 | alice 与 bob 独立 Session | 401/403/404 的解释和例子 |
| 4 | 一半成功、一半失败怎么办 | 模块 05 | 取消事务与受控事件失败 | 回滚前后的状态和事件 |
| 5 | 两人同时接单怎么办 | 模块 06 | 条件更新、独立事务竞争、完成 | 唯一胜者与事件数量 |
| 6 | 怎样交给别人运行 | 模块 07、08 | 分页、错误编号、报告、部署流程 | 新环境操作清单与已知限制 |

前端页面暂停，不作为本阶段课堂的前置条件。PowerShell 与 DBeaver 已能完整练习后端合同。后续恢复前端时，再把每个按钮映射到已验证的接口。

## 二、每节开头用具体问题引入

第一节问：“POST 返回的 id 是谁生成的？”先让学生猜，随后找到 AUTO_INCREMENT、useGeneratedKeys、TicketResponse，不急着背框架定义。

第二节问：“DBeaver 已经连通，为什么 Java 还是连接失败？”让学生区分两个客户端、两个进程环境，再检查配置。

第三节问：“我把 actorId 改成 1001，是不是就成了 alice？”沿请求参数到 CurrentUser 的路径证明身份来源。

第四节问：“状态已经取消，但事件没写成功，该怎么处理？”先画两条 SQL，再引入同一个事务，不从事务传播枚举开始讲。

第五节问：“两个线程都看到 OPEN，为什么都不能算成功？”画出交错执行顺序，再让学生在 UPDATE 中补状态条件。

第六节问：“电脑上有 BUILD SUCCESS，为什么还不能说项目完成？”区分旧报告、新代码、当前运行进程与新环境部署。

## 三、分层练习与参考答案

### 入门：能定位、能解释

1. final 字段与 final 方法有什么区别？字段引用不可重新赋值；方法不可被子类重写。不要把 final 理解成对象递归不可变。
2. AtomicLong 还能不能当数据库主键？它可用于同一进程的原子计数，但不能替代当前持久化设计中的 MySQL 自增主键。
3. 为什么测试放 src/test/java？测试依赖与正式编译分开，JUnit 不需要成为正式业务依赖。
4. 为什么返回 id 字符串？响应合同与数据库类型各有职责，字符串也避免某些客户端大整数精度问题；当前项目已选择字符串合同。

### 实操：能复现、能检查

1. 创建一张带中文描述的工单。交付：201、查询结果、DBeaver 同一 id 的行。
2. 用 bob 查询 alice 的单。交付：404、alice 仍能查询、数据库未变化。
3. 取消同一张单两次。交付：第一次204、第二次409、只有一个 CANCEL。
4. 用 agent1 接单，再由 agent2 查询该单。交付：agent1 可见、agent2 不可见、assignee_id=2001。
5. 将 page 改为 abc、0，分别解释失败层次。交付：两种400及 code，对应 MVC 转换与 Service 范围校验。

### 进阶：能发现不完整的证明

错误说法：“Service 抛异常，所以事务一定回滚。”修正：还必须检查真实数据库状态和事件，证明前面的写入被撤销。

错误说法：“单线程调用两次 claim，一次成功一次失败，所以并发安全。”修正：还需两个独立事务同时竞争，检查唯一胜者和事件数量。

错误说法：“COUNT 有权限过滤，列表没有也没关系。”修正：数据与总数都必须使用同样的可见条件，否则泄露数据或产生不一致分页。

错误说法：“收到 500 后立即重试 POST 最安全。”修正：网络和响应错误可能发生在提交之后，应先查询结果确认；本项目不提供通用幂等键合同，不能无条件重复创建。
