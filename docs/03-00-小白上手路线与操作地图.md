## 操作地图：先弄清在哪个窗口执行

| 工具 | 用途 | 示例 | 不能替代什么 |
| --- | --- | --- | --- |
| IDE / 代码编辑器 | 修改 Java、XML、配置、测试 | TicketService.java | 保存文件不等于重新运行服务 |
| PowerShell A | 设置环境、运行测试或启动 Java | .\mvnw.cmd spring-boot:run | 启动成功不代表所有接口成功 |
| PowerShell B | 调用接口、运行验证脚本 | .\scripts\Test-TicketClaim.ps1 | HTTP 返回成功仍需核对数据库 |
| DBeaver SQL 编辑器 | 执行 SQL、查看字段与业务记录 | SELECT ... FROM tickets | DBeaver 连接成功不等于 Java 配置成功 |

A 启动服务后一直占用窗口是正常现象。不要为了继续输入命令再启动第二个服务；另开 B。停止时在 A 按 Ctrl+C。环境变量属于各自的终端，A 的设置不会自动出现在 B 或 IDE。

复制命令时只复制代码块内容，不复制 PS C:\...>、日志中的 [INFO]、Markdown 星号或多余反斜杠。Wrapper 文件名是 mvnw.cmd，正确命令为 .\mvnw.cmd test。

## 先背下这个业务边界

~~~text
OPEN ──接单──> IN_PROGRESS ──完成──> RESOLVED
  └──取消──> CANCELLED
~~~

USER 创建、查询自己的工单，只能取消自己的 OPEN。AGENT 可以看到未被接走的 OPEN 与分配给自己的工单，只能完成自己负责的 IN_PROGRESS。不能重新打开、转派、批量改状态；当前没有用户表、注册和管理员模块。

登录用户来自 Session，不能靠传 creatorId 或 actorId 冒充。创建接口中的状态由服务端固定为 OPEN。查询返回的 id 是字符串，数据库存储的是 BIGINT，这两者并不矛盾。

## 每节课的固定学习动作

1. 用一句话说出本节解决的问题，例如“服务一重启工单就没了”。
2. 找到输入、业务规则、SQL、响应分别在哪个文件。
3. 预测正常结果，再预测一个失败结果。
4. 按本节步骤操作，保存 HTTP 状态和对应工单编号。
5. 用 SQL 核对状态与事件；不要只看页面或控制台文字。
6. 写下“为什么”，不是只抄最终代码。

验收记录可以使用：日期 / 当前代码版本或差异 / 环境 / 命令 / 预期 / 实际 / 工单编号 / 结论。编号 34、56、87 是历史练习数据，不是下次必须得到的编号。
