## 在运行服务的窗口设置密码

如果旧服务正在运行，先按 Ctrl+C。当前代码启动还需要 LAB_AGENT1_PASSWORD、LAB_AGENT2_PASSWORD，请先按 [接单练习第 3 节](03-处理人接单与并发练习.md) 设置它们，再在保留 DB_* 环境变量的同一个窗口执行下面的 alice、bob 设置和启动命令：

~~~powershell
$alicePassword = Read-Host '设置 alice 登录密码' -AsSecureString
$env:LAB_ALICE_PASSWORD = [System.Net.NetworkCredential]::new('', $alicePassword).Password
$alicePassword.Dispose()
Remove-Variable alicePassword
$bobPassword = Read-Host '设置 bob 登录密码' -AsSecureString
$env:LAB_BOB_PASSWORD = [System.Net.NetworkCredential]::new('', $bobPassword).Password
$bobPassword.Dispose()
Remove-Variable bobPassword
.\mvnw.cmd spring-boot:run
~~~

这两个密码由你设置，不要填写 MySQL 的 root 或 ticket_app 密码。变量只在当前终端及其子进程生效；新终端需要重新提供配置。服务重启后原 Session 失效，需要重新登录。

## 理解 Session 和 CSRF 的请求顺序

| 顺序 | 请求 | 用途 |
| --- | --- | --- |
| 1 | GET /api/csrf | 创建会话并取得登录所需 token |
| 2 | POST /api/login | 表单提交 username、password，携带 token 和同一会话 Cookie |
| 3 | GET /api/csrf | 登录后重新取得 token，继续使用同一会话 |
| 4 | GET /api/me | 查看当前用户编号和用户名 |
| 5 | POST /api/tickets 或取消接口 | 携带会话 Cookie 和 token 请求头 |
| 6 | POST /api/logout | 携带 token 退出并销毁会话 |

登录使用 application/x-www-form-urlencoded，创建工单仍使用 application/json。token 接口返回 headerName 和 token，客户端据此设置请求头。GET 查询需要登录会话，不要求 CSRF 请求头。

未登录返回 401，已登录但角色不符或 CSRF 无效返回 403；登录失败不跳转 HTML 页面。不要关闭 CSRF 来解决请求失败，要检查是否复用 WebSession，并在登录后重新取 token。

## PowerShell 验证脚本的请求头注意事项

WebSession 会保留之前通过 -Headers 传入的请求头，因此仅省略 -Headers 不能保证不发送 CSRF token。脚本已在缺少 token 的检查前显式移除会话中的 CSRF 头，同时保留登录 Cookie；后续合法取消再显式传入 token。

2026-10-31 使用本机请求头检查端点，在 Windows PowerShell 5.1 与 PowerShell 7.6.4 均复现了请求头保留现象，并确认移除后不再携带 token、Cookie 仍保留。本次脚本修复没有重新执行 Java 构建或完整双账号流程。

若旧脚本曾在“预期 403，实际 204”处停止，该工单可能已经取消。请从头重新运行修复后的脚本，使用新创建的练习工单，不要在原工单上接着重试取消。
