## 1. 完成操作的规则

接口：POST /api/tickets/{id}/resolve，无需 JSON 请求体，成功返回 204。

- 必须登录为 AGENT，并携带有效 CSRF token。
- 必须是当前工单的处理人，且状态为 IN_PROGRESS。
- 成功后状态变为 RESOLVED，保留创建人和处理人编号，并新增 RESOLVE 记录。
- 操作者来自登录会话；传 actorId、assigneeId 或 status 不能替换身份或指定结果。
- 更新状态与插入记录共用一个事务；记录失败时状态恢复 IN_PROGRESS，先前已提交的 CLAIM 保留。

| 情况 | 状态码 |
| --- | --- |
| 未登录完成工单 | 401 |
| USER 尝试完成，或处理人缺少有效 CSRF | 403 |
| 别人的已接单工单、不存在或不可见的工单 | 404 |
| 对可见的未接单工单直接完成，或重复完成 | 409 |
| 当前处理人完成自己的 IN_PROGRESS 工单 | 204 |

完成后，创建人和处理人仍可查看详情；其他处理人不可见。已完成的工单不能再次接单、完成或取消。

## 6. 这次要理解的 SQL

~~~sql
UPDATE tickets
SET status = 'RESOLVED'
WHERE id = ?
  AND assignee_id = ?
  AND status = 'IN_PROGRESS';
~~~

WHERE 同时检查处理人和状态，所以不能完成别人的工单，也不能重复完成。Service 检查更新行数，只有更新一行后才插入 RESOLVE。即使同一处理人同时发送两个完成请求，也只有一个请求能成功改变状态，另一个得到冲突。

代码阅读顺序：TicketController.resolve → TicketService.resolve → TicketMapper.resolveAssignedTicket → mapper/TicketMapper.xml → TicketEventMapper。
