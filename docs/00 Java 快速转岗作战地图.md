# 00 Java 快速转岗作战地图

你已经做了 9 年前端，现在要补的是 Java 后端交付能力。最值得先完成的事情，是把一个熟悉的页面需求，从接口、数据库一路做到可测试、可部署。

**这套笔记的目标：尽快具备投递 Java 全栈岗位、讲清项目、独立修改后端需求的能力。**

它不是 Java 百科，也不承诺几周就能找到工作。下面的六周安排是训练预算；哪一关没有通过，就补哪一关，不靠跳过难点制造进度。

## 一、先知道自己要交付什么

贯穿项目是一套小型工单系统。

用户提交问题，处理人接单、解决，创建人可以取消尚未被接走的工单。你需要把这些规则落实到接口和数据库，而不只是做出几个页面。

完成后，应当留下四样东西：

- 一套能启动、能演示的代码。
- 一份别人能照着操作的运行说明。
- 一组覆盖成功与失败场景的测试。
- 一次能够脱离稿件讲清楚的项目演示。

第一轮不要加支付、商城、复杂工作流，也不用重写前端组件库。

## 二、六周只抓一条主线

建议按每周 20–25 小时安排，总计约 120–150 小时。如果每周只能投入 10 小时，就拉长周期，别把同样的任务压缩成“速成”。

### 第 1 周：用 Java 写对一条业务规则

学习变量、方法、类、枚举、集合和异常。先知道代码为什么这样写，再认识 Maven 的依赖与目录。

**交付物：内存版工单创建、查询、取消。**

验收时，关闭参考答案，自己实现“只有创建人能取消 OPEN 工单”，并说明操作失败后状态是否变化。

阅读：[[01 前端转 Java：用工单取消学会基础语法]]。

### 第 2 周：把方法变成 HTTP 接口

认识 Spring Boot、Controller、Service、请求对象和参数校验。不要一上来设计万能架构。

**交付物：创建与查询接口。**

正确输入能够成功，空标题被拒绝，不存在的编号返回 404。能指出请求从哪一个方法进入、在哪里执行逻辑。

阅读：[[02 第一个 Java 接口：创建与查询工单]]。

### 第 3 周：把数据真正存下来

学习 SQL 的查询、插入、更新、排序与分页，再接入 MySQL 和 MyBatis。搞清楚重启之后数据为什么还在。

**交付物：数据库版工单接口，以及操作记录。**

必须验证一次失败回滚：如果操作记录写入失败，工单状态不能已经改成功。

### 第 4 周：补上权限和状态竞争

接入登录身份，判断谁能操作哪张工单。处理“两个处理人同时接单”以及“重复点击取消”。

**交付物：不能越权、不能非法跳状态的完整业务流程。**

第 3–4 周统一按照 [[03 工单项目交付：数据库、权限、事务与部署]] 推进。

### 第 5 周：让项目可验证、可排错

补齐自动化测试、日志、环境配置和部署说明。前端只做登录、列表、详情、操作按钮等必要页面。

**交付物：能按说明重建的演示环境。**

不要用“我的电脑能跑”作为验收。换一个干净环境，或让同事按说明操作一次，记录缺失步骤。

### 第 6 周：用项目准备面试

练习增加一个小需求，整理一次真实的排错记录。把技术问题落到自己的代码，而不是背一串名词。

**交付物：项目演示、真实简历、面试复盘。**

阅读 [[04 Java 转岗面试：用项目回答关键问题]] 和 [[05 Java 快速转岗：投递、复盘与 AI 学习法]]。

## 三、先学什么，暂缓什么

### 必须能动手写

Java 常用语法、集合与异常；接口与参数校验；SQL 与持久化；权限、事务、状态流转；测试与基本排错。

### 必须能结合代码解释

依赖注入为什么方便替换实现，事务在什么条件下生效，索引为什么要对应查询条件，为什么先查询再更新仍可能冲突。

遇到解释不清的点，就做一个小实验。不要用背出定义替代验证。

### 第一轮暂缓

微服务拆分、复杂分布式架构、框架源码通读、JVM 深度调优、Kubernetes，以及没有实际需求的消息队列和缓存。

AI 应用功能也先不加。先把“取消一张工单”做可靠，比给不可靠的系统加一个聊天框更有训练价值。

这些是本计划的取舍，不代表所有岗位都不要求。目标岗位反复出现的要求，需要在后续定向补齐。

## 四、每天怎么学，才不变成只看文章

工作日可以采用一个两小时学习块：

1. 20 分钟阅读，只解决当天的一个问题。
2. 60 分钟写代码，先自己尝试。
3. 25 分钟验证成功、失败和边界情况。
4. 15 分钟记下错误原因、修复方法、明天第一步。

每周另留时间做一次完整演示和查漏补缺，凑足自己的实际预算。

每天结束只问一句：**今天多了哪一项我可以独立完成的能力？**

“看了两小时视频”是投入，不是成果。

## 五、学习环境只选一套

本套示例以 Java 21 为教学基线，不追逐语言新特性。第 2 篇使用 Spring Boot 4.x 的稳定版本创建工程；接数据库时，MyBatis Starter 要选择与它兼容的 4.0 系列。

具体补丁版本以建工程时的官方兼容说明为准，写进项目运行说明，并保留生成的 Maven Wrapper。已有公司项目则服从项目版本，不为跟教程擅自升级。

版本依据见 [Spring Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html) 和 [MyBatis Starter 兼容表](https://mybatis.org/spring-boot-starter/mybatis-spring-boot-autoconfigure/)。本次参考核对日期为 2026-10-17；不是对未来版本的保证。

## 六、今天就做这三件事

- [ ] 整理 10 个自己愿意投递的岗位，区分“必需”和“加分”，不统计无意投递的岗位。
- [ ] 预留本周真实可投入的时间；不足就调整计划。
- [ ] 阅读第 1 篇，运行并改写工单取消示例，记录第一个错误。

先完成一个小闭环，再扩展能力。投递准备从第一周开始，不等整套内容全部学完。
