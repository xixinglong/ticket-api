## 1. 本次代码变化

调用顺序：HTTP 请求 → TicketController → TicketService → TicketMapper → MySQL。

- pom.xml：增加 MyBatis Starter 4.1.0 和 MySQL JDBC 驱动。选用版本的发布 POM 使用 Spring Boot 4.1.0，本项目使用 Boot 4.1.2；实际运行验证待完成。
- TicketRow.java：表示本阶段使用的数据库列；MyBatis 通过 setter 回填查询结果和自增编号。
- TicketMapper.java：声明插入和按编号查询方法。
- mapper/TicketMapper.xml：编写 SQL，显式映射 creator_id 到 creatorId，使用 #{} 绑定参数。
- TicketService.java：调用 Mapper，取代原来的 Map 和 AtomicLong。接口中的 id 仍是字符串。
- application.properties：从环境变量读取连接信息。

本阶段没有登录，creator_id 临时固定为 1001，仅供本地练习。以后应改为服务端获取的登录用户编号。创建时 status 为 OPEN，assignee_id 留空，created_at 由数据库填写。创建接口暂不写 ticket_events。取消接口与事务回滚验证已在后续练习中接入，见《03-取消工单与事务练习》。

## 2. 在 PowerShell 设置数据库连接

前提：本机 MySQL84 服务运行，ticket_lab 中已经建好 tickets 和 ticket_events，并包含前面添加的 description 列。应用使用 ticket_app 账号。

在项目目录打开 PowerShell，执行：

~~~powershell
Set-Location 'C:\xixl-study\java-labs\ticket-api'
$env:DB_URL = 'jdbc:mysql://127.0.0.1:3306/ticket_lab'
$env:DB_USER = 'ticket_app'
$dbPassword = Read-Host '输入 ticket_app 的数据库密码' -AsSecureString
$env:DB_PASSWORD = [System.Net.NetworkCredential]::new('', $dbPassword).Password
Remove-Variable dbPassword
~~~

密码使用此前配置 DBeaver 时的 ticket_app 密码，可在本机的 C:\ProgramData\MySQL\credentials\连接信息.txt 中查看。不要把密码粘贴到笔记、聊天或源码里，也不要输出 DB_PASSWORD 的值。

这些变量只对当前 PowerShell 及其启动的程序生效。另开终端或通过 IDE 启动时，需要单独设置。DBeaver 中保存的连接信息不会自动传给 Java。

下面的命令由你执行，本次代码修改没有自动运行 Maven。


TicketServiceTest 不连数据库；TicketApiApplicationTests 会连接环境变量指定的数据库，验证主键回填、两张工单分别查询、空描述和中文描述保存。集成测试结束会回滚插入的数据，自增编号可能出现空缺。

## 4. 在第二个 PowerShell 发送 HTTP 请求

~~~powershell
$base = 'http://127.0.0.1:8080'
$json = @{ title = 'Login page is blank'; description = 'Blank after signing in' } | ConvertTo-Json
$created = Invoke-WebRequest -UseBasicParsing -Method Post -Uri "$base/api/tickets" -ContentType 'application/json' -Body $json
$created.StatusCode
$ticket = $created.Content | ConvertFrom-Json
$ticket
Invoke-RestMethod -Method Get -Uri "$base/api/tickets/$($ticket.id)"
~~~

预期 POST 状态码为 201，查询返回相同 id、title、status 和 description。id 不一定从 1 开始，不要手工假定编号。

## 5. 在 DBeaver 检查同一条记录

确认选中本机 127.0.0.1 的 ticket_lab 连接。将下面的 123 替换为刚才响应中的实际 id，再执行整条 SQL：

~~~sql
SELECT id, title, description, creator_id, assignee_id, status, created_at
FROM ticket_lab.tickets
WHERE id = 123;
~~~

应看到刚才创建的数据，creator_id 为 1001，status 为 OPEN。这一步证明 HTTP 创建的数据已经写入 MySQL。

## 6. 验证重启后还能查询

1. 保持发送 HTTP 请求的第二个 PowerShell 窗口打开，其中保存了 $ticket。
2. 在运行 Java 的第一个窗口按 Ctrl+C 停止服务。
3. 在第一个窗口重新运行 .\mvnw.cmd spring-boot:run，等待启动成功。
4. 回到第二个窗口，只执行查询命令，不重新创建工单：

~~~powershell
Invoke-RestMethod -Method Get -Uri "$base/api/tickets/$($ticket.id)"
~~~

重启后仍返回原工单，才完成这次持久化验证。若第二个窗口已关闭，请重新设置 $base，并把查询 URL 中的编号写成之前记下的实际 id。
