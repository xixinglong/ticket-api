# 前端工作台：登录、工单与用户管理

## 学习目标

本课把现有后端接口接入浏览器。使用 Spring Boot 静态资源目录，不另起前端部署服务；页面和 API 同源，沿用 Session Cookie 与 CSRF 防护。

## 文件与职责

| 文件 | 职责 |
| --- | --- |
| src/main/resources/static/index.html | 登录表单、列表、分页、弹窗 |
| src/main/resources/static/app.css | 桌面与手机布局、状态标记、表格滚动 |
| src/main/resources/static/app.js | API 请求、角色视图、表单提交与错误处理 |
| SecurityConfig.java | 仅放行明确列出的静态资源，API 继续校验身份与角色 |

页面不是权限边界。隐藏客服的新建按钮不能代替后端权限校验，用户修改 JavaScript 也不能取得不属于自己的权限。

## 登录流程

1. 页面启动请求 /api/me，已有会话直接进入列表，没有会话显示登录表单。
2. 登录前请求 /api/csrf，在同一 Cookie 会话中提交表单登录。
3. 登录后重新读取身份，每次写操作获取当前 CSRF token，不能复用登录前的旧 token。
4. 退出调用后端 /api/logout，不能只隐藏页面。
5. 接口返回 401 时清理页面身份、关闭弹窗并回到登录页。503 等错误保留可重试状态。

## 三种视图

- USER：分页查看自己的工单、新建、查看详情、取消待处理工单。
- AGENT：查看可见工单、接单、完成自己正在处理的工单。
- ADMIN：用户分页、创建普通用户或客服、确认启停、重置密码；管理员行不显示修改入口。

表单使用浏览器基本校验，但最终规则仍由后端决定。前端不保存密码到 localStorage，关闭弹窗后移除表单字段。动态文本统一转义，不把用户输入直接当作 HTML。

## 状态与交互

列表支持每页 10、20、50 条、上一页、下一页和刷新。请求序号用于丢弃迟到响应，避免旧分页请求覆盖新结果。无数据时显示空列表状态，按钮提交期间禁用，减少重复写入。

操作失败显示服务端安全错误及请求编号。并发状态冲突需要刷新后重新操作，前端不能自行假定操作成功。手机表格保留列宽并在表格区域横向滚动，不挤压所有列到不可读的宽度。

## 验证练习

1. 使用两个独立浏览器会话登录普通用户和管理员，重置普通用户密码，点击旧会话刷新，应返回登录页。
2. 普通用户创建工单，客服接单并完成，普通用户刷新后核对状态。
3. 输入包含 HTML 符号的标题，确认显示为普通文字，不执行脚本。
4. 删除请求中的 CSRF 头，确认后端拒绝写入。
5. 在手机视口检查表格滚动、弹窗、分页和登录表单。

本课不是生产交付终点。搜索筛选、事件时间线、账号操作审计、密码恢复和前端自动化回归脚本仍可后续扩展。部署前须完成用户管理数据库迁移，不要将新版应用连接到缺少 auth_version 的旧库。

## 可重复浏览器验收

scripts/verify-frontend.cjs 使用 Playwright 和本机 Chrome，在 18081 隔离预览环境执行核心流程。先完成独立数据库验收并启动预览，再运行 node scripts/verify-frontend.cjs；Playwright 不在默认模块路径时通过 NODE_PATH 指定已安装的包目录。

脚本验证工单流转、文本转义、账号启停、密码重置与旧会话失效、分页及移动端布局。报告和截图保存在 target/frontend-acceptance，不进入版本库。测试样本带时间戳并保留在独立库，不能将该脚本改为连接日常业务库。
