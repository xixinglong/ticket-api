# 03-用户模块实施与双机迁移记录

## 范围与设计

此文件记录用户模块实施，不修改公共课件，也不将 Mac 的验收结果视为 Windows 已验收。

登录身份由 MyBatis 查询 users 表提供，替代代码中的固定账号分支。users 包含 id、唯一用户名、password_hash、role、enabled 和创建时间；密码采用 Spring Security 的 `{bcrypt}` 格式，不保存明文。角色限定 USER/AGENT，用户名区分大小写。

迁移保留 alice=1001、bob=1002、agent1=2001、agent2=2002。工单 creator_id、assignee_id 及事件 actor_id 都关联 users.id，禁止删除仍被业务数据引用的用户。外键只保证用户存在，不代替 Service 的角色与归属检查。

Session 和 CSRF 机制保持不变。enabled=false 会阻止新登录；已建立的 Session 不会因为数据库更新而立即撤销。改密码、改角色也不会自动刷新已有 Session；需要退出重新登录，或重启当前单实例服务使全部 Session 失效。本阶段没有实现用户管理接口、注册、找回密码或即时会话撤销。

## 迁移前须知

1. 先停应用和其他写入程序，并备份目标库。不要对正在使用的业务库执行自动化测试。
2. 确认 MySQL 8.0.16 以上，以便 CHECK 约束真正生效；本机验证使用 8.4.13。
3. DB_URL 必须明确目标库。DB_USER/DB_PASSWORD 是数据库管理员凭据，不是应用登录账号。
4. LAB_ALICE_PASSWORD、LAB_BOB_PASSWORD、LAB_AGENT1_PASSWORD、LAB_AGENT2_PASSWORD 仅供首次迁移初始化；使用各自电脑已有登录密码，不要把 Mac 密码复制到 Windows。
5. 迁移先检查业务表中的用户引用。发现四个预设编号以外的旧编号会停止，要求人工确认映射，不自动改号或丢弃数据。

迁移工具是 `scripts/MigrateUsers.java`，表定义是 `sql/02-users.sql`。它用参数绑定写入密码哈希，并检查已有 id/用户名/角色映射。重复执行保留已有密码和 enabled 状态，不重置账号；已存在的外键不会重复添加。

MySQL DDL 隐式提交，因此整次迁移不是一个可整体回滚的事务。失败后保留备份和日志，先核对 users 及外键状态，修正原因后再运行；不要靠关闭 FOREIGN_KEY_CHECKS 强行通过。当前工具面向四个练习账号迁移，不是通用多版本数据库迁移框架。

## Mac 操作

已有本机凭据配置时：

```sh
cd /Users/mac/xixl-work/xixl-study/ticket-api
launchctl bootout "gui/$(id -u)/local.ticket-api"
python3 scripts/migrate-users-macos.py
launchctl bootstrap "gui/$(id -u)" "$HOME/.local/share/ticket-api/service.plist"
python3 "$HOME/.local/share/ticket-api/verify.py"
```

前提是已经在独立库运行 `python3 scripts/verify-macos.py` 通过，并生成新版 Jar。迁移脚本使用 root.cnf 读取管理员凭据，accounts.json 读取原应用密码。备份写入 `~/.local/share/ticket-api/backups`，默认仅当前用户可读。备份含业务数据，迁移后的备份还会含密码哈希，不应提交或公开。

日常服务只需要 DB_URL、DB_USER、DB_PASSWORD，不再需要 LAB_* 环境变量。旧启动器即便仍导出 LAB_*，新版服务也不会用它们重置数据库密码。accounts.json 此后仅是初始化时的本机密码记录；手动修改数据库密码后，该文件不会自动同步。

## Windows 操作

Windows 尚未执行本次验收。保留现有项目位置和 Java 21 环境，在该电脑同步代码后，先停止服务、备份业务库，再在独立测试库验证。

PowerShell 中先安全设置 DB_* 和四个 LAB_* 环境变量，不把真实值写入共享脚本或笔记。独立测试库先执行 `sql/01-schema.sql`；已有业务库不要重复执行该文件。

```powershell
# 在该电脑的项目根目录执行
.\mvnw.cmd dependency:build-classpath "-Dmdep.outputFile=target/migration-classpath.txt"
$cp = (Get-Content target/migration-classpath.txt -Raw).Trim()
java --class-path $cp scripts/MigrateUsers.java
```

测试库初始化时，四个 LAB_* 分别设为 `test-alice-password`、`test-bob-password`、`test-agent1-password`、`test-agent2-password`，仅供测试，然后运行：

```powershell
.\mvnw.cmd test package
```

测试通过后切回业务库管理员 DB_* 和该电脑真实初始化密码执行迁移。启动应用前切回权限受限的 ticket_app 数据库账号，运行生成的 Jar。账号已有密码时，重复迁移不会修改密码，因此不要把测试库和业务库混用。

如果失败需要恢复旧版：先停止服务，保留失败现场，优先在另一个数据库恢复迁移前备份并核对数据，再将旧版应用指向恢复库。不要在有新写入的情况下直接覆盖原库。
